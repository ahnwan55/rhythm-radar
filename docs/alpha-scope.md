# 알파테스트 범위

## 1. 목적

알파테스트의 목적은 운영자가 직접 검수 가능한 제한된 점포에서 기종별 대기 상태 제보가 실제 방문 판단에 유용한지 검증하는 것입니다. 알파 1차는 서울·부천권으로 범위를 좁히고, 인천권은 알파 2차 테스트 예정 범위로 분리합니다.

알파에서는 완전한 실시간 정확성보다 다음 항목을 우선 검증합니다.

- 이용자가 부담 없이 대기 상태를 제보할 수 있는가
- 최근 제보가 다른 이용자의 방문 결정에 도움이 되는가
- 관리자 검수 방식으로 기기 가동 정보를 신뢰성 있게 유지할 수 있는가
- 최소한의 악성 제보 대응만으로 초기 운영이 가능한가

## 2. 대상 점포

| 점포 | 권역 | 알파 포함 상태 |
| --- | --- | --- |
| 노량진 어뮤즈타운 | 서울 | 1차 포함 |
| 태릉입구역 비트연구소 T | 서울 | 1차 포함 |
| 한성대 우리게임장2 | 서울 | 1차 포함 |
| 부천 어택 | 경기 부천 | 1차 포함 |
| 부천 P2존 | 경기 부천 | 1차 포함 |
| 주안 CPU 게임랜드 | 인천 주안 | 1차 제외, 2차 알파테스트 예정 |

점포별 취급 기종과 기체 수는 알파 개시 전에 관리자 검수로 초기 등록합니다. 물리적으로 존재하는 전체 기체 수와 최신 온라인 대기열 추적 대상 기체 수는 분리하여 관리합니다.

주안 CPU 게임랜드는 인천권 주요 리듬게임 점포로 알파 2차 테스트 예정에 둡니다. 알파 1차에서는 운영자 직접 방문과 반복 확인이 가능한 서울·부천권 동선을 우선하므로, 직접 검수 전까지 기종/기체 수와 대기 상태를 공개 확정하지 않습니다.

## 3. 사용자 역할

| 역할 | 할 수 있는 일 |
| --- | --- |
| 비로그인 이용자 | 점포, 기종, 최신 대기 상태, 체감 혼잡도 조회 |
| 로그인 이용자 | 조회, 기종별 대기 상태 제보, 이상 대기 제보 신고, 기기 정보 변경 증거 사진 제보 |
| 관리자 | 기종 및 기체 수 검수, 사진 제보 승인/반려, 신고 검토, 제보 로그 확인 |

## 4. 대기 상태 정책

대기 상태는 정확한 대기 인원을 요구하지 않고, 빠르게 판단 가능한 구간으로 받습니다.

| 상태 코드 초안 | 표시 문구 | 의미 |
| --- | --- | --- |
| `EMPTY` | 빈 기기 있음 | 가동 기기 중 바로 플레이 가능한 기기가 관찰됨 |
| `IN_USE_NO_QUEUE` | 플레이 중 / 대기 없음 | 기기는 사용 중이나 기다리는 이용자는 관찰되지 않음 |
| `LOW` | 대기 적음 | 짧은 순환 내 플레이 가능하다고 체감됨 |
| `MEDIUM` | 대기 보통 | 방문 판단에 영향을 줄 정도의 대기 |
| `HIGH` | 대기 많음 | 상당한 대기가 예상됨 |
| `VERY_HIGH` | 대기 매우 많음 | 방문을 재고할 정도의 높은 대기가 관찰됨 |
| `UNKNOWN` | 확인 필요 | 유효한 최근 제보가 없거나 판단 불가 |

대기 상태 구간은 정확한 시간이나 인원 기준을 뜻하지 않습니다. 대기 상태 제보는 작성 후 30분 동안 최신 정보로 인정하며, 이용자 화면에서는 제보 시각을 함께 표시하여 정보의 신선도를 판단할 수 있게 합니다. `UNKNOWN`은 시스템 표시용 상태이며 일반 이용자가 직접 선택하는 제보값으로 받지 않습니다.

## 5. 포함 범위

- 5개 알파 1차 대상 점포와 등록 기종의 목록 조회
- 점포별 기종 단위 최신 대기 상태 조회
- 로그인 이용자의 대기 상태 제보
- 제보 시각 및 제보 로그 저장
- 대기 상태 제보 30분 유효 시간과 만료 후 `n분 전 제보` 표시
- 이상 대기 상태 제보 신고와 관리자 검토
- 검수된 전체 기체 수, 최신 온라인 추적 대상 기체 수, 현재 가동 중인 추적 대상 기체 수, 추적 제외 기체 수 관리
- 기체 수, 버전, 가동 상태 변경에 관한 사진 첨부 제보와 관리자 승인 흐름
- 가동 중인 최신 온라인 추적 대상 기체 수와 최신 대기 상태에 기반한 체감 혼잡도 표시
- 동일 이용자 반복 제보와 전체 제보 과밀을 막기 위한 쿨타임

## 6. 제외 범위

알파에서는 다음 기능을 제공 대상으로 삼지 않습니다.

- 정확한 대기 인원 또는 대기 시간 예측
- 이용자 평판 점수, 신고 누적에 따른 자동 제재
- 실시간 위치 인증 또는 현장 방문 인증
- 점포 외부 혼잡도, 영업시간, 교통정보 통합
- 점주 전용 계정 또는 점주 직접 수정 기능
- 알림, 즐겨찾기, 추천 경로, 커뮤니티 기능
- 알파 대상 외 점포의 일반 이용자 등록
- 인천권 점포의 알파 1차 공개 운영
- 일반 대기 상태 제보의 사진 첨부 또는 사진 검증
- 점포 전체 혼잡도 집계
- 기종별 수요 등급을 이용한 혼잡도 보정
- 관리자 화면을 통한 신규 점포 추가. 알파에서는 코드 또는 정적 데이터 갱신으로 처리

## 7. 운영 및 신뢰성 정책

### 이용자 제보

- 대기 상태 제보는 로그인 이용자만 작성할 수 있습니다.
- 알파 로그인 제공자는 카카오로 고정합니다. 기존 개발 경험과 부계정 사용 리스크를 고려한 선택입니다.
- 각 제보에는 이용자, 점포, 기종, 선택 상태, 작성 시각을 기록합니다.
- 대기 상태 제보에는 사진을 첨부하지 않습니다.
- 일반 이용자는 `UNKNOWN`을 선택할 수 없습니다. `UNKNOWN`은 유효한 제보가 없거나 시스템이 판단할 수 없을 때 표시하는 값입니다.
- 같은 점포-기종에 대해 직전 제보자가 같은 이용자면 3분 쿨타임을 적용합니다.
- 같은 점포-기종에 대해 직전 제보자와 다른 이용자면 1분 쿨타임을 적용합니다.
- 3분과 1분은 정확한 플레이 시간 예측이 아니라 알파 운영용 제보 갱신 단위입니다.
- 최신 제보 유효 시간은 30분입니다.
- 제보가 만료되면 체감 혼잡도 계산에는 사용하지 않고 `정보 부족`으로 처리합니다. 다만 마지막 제보값과 제보 시각은 `n분 전 제보` 형식의 참고 정보로 표시할 수 있습니다.

### 기기 정보 변경

- `totalMachineCount`, `trackedMachineCount`, `activeTrackedMachineCount`, `untrackedMachineCount`는 관리자 승인된 데이터만 공개 상태에 반영합니다.
- 추적 포함 여부는 신버전 온라인 업데이트 여부만으로 판단하며, 기체의 신구 여부 자체는 계산 기준으로 사용하지 않습니다.
- 알파에서 대기열 추적에 포함할 수 있는 기체/버전 상태는 `CURRENT_VERSION_ONLINE`뿐입니다.
- 신기체와 구기체가 같은 신버전을 가동하더라도 수요가 다르면 `machineGroups`로 분리해 표시할 수 있습니다.
- 기타도라처럼 아레나 모델과 구기체 사이에 마이너 버전 차이가 있으면 알파에서는 아레나 모델만 최신 버전 추적 대상으로 삼고, 구기체는 참고 정보로 표시합니다.
- 마이너 버전 차이, 구버전, 업데이트 중단, 오프라인 또는 상태 미확정 기체는 매장 참고 정보로 표시할 수 있으나 대기열 및 체감 혼잡도 계산에는 포함하지 않습니다. 추적 제외 사유는 `untrackedMachineCount`, `machineGroups`, `notes`로 안내합니다.
- 이용자는 기체 수, 버전, 가동 상태 변경처럼 공개 기준값에 영향을 주는 중요 정보를 사진과 함께 제보할 수 있습니다.
- 관리자는 사진과 제보 내용을 검토해 승인하거나 반려하며, 처리 이력을 남깁니다.
- 증거 사진은 기기 정보 검수 목적으로만 사용하며, 공개 화면에는 노출하지 않습니다.
- 알파에서는 관리자 1명만 증거 사진을 열람하고 승인/반려를 처리합니다.
- 증거 사진은 접수 시점 기준 2주 뒤 자동 삭제합니다.
- 알려진 구버전, 마이너 버전 차이, 업데이트 중단 기체는 추적 제외 참고 정보로 기록합니다.

### 분탕 대응

알파 단계에서는 복잡한 신뢰도 모델을 도입하지 않습니다. 기본 방어선은 다음 네 가지입니다.

- 로그인 필수
- 제보 로그 저장
- 제보 쿨타임
- 이상 제보 신고와 관리자 검토

신고는 대기 상태 제보인 `WaitReport`를 대상으로 하며, 신고가 접수되어도 자동으로 숨기지 않습니다. 관리자가 신고 내용을 확인한 뒤 대상 제보를 유지하거나 최신 상태 계산에서 제외할 수 있습니다.

운영 중 반복적인 허위 제보 사례가 관찰되면 계정 제한, 신고 남용 제한, 신뢰도 가중치 도입을 후속 범위로 검토합니다.

## 8. 체감 혼잡도

체감 혼잡도는 이용자에게 기종별 플레이 어려움을 요약해 보여 주기 위한 파생 정보입니다.

- 입력값: 승인된 `trackedMachineCount`, `activeTrackedMachineCount`, 유효한 최신 대기 상태
- 원칙: 동일한 대기 상태라도 가동 중인 최신 온라인 추적 대상 기체가 적으면 더 혼잡하게 느껴질 수 있도록 반영
- 제외: 구버전, 업데이트 중단 또는 오프라인 기체는 입력값과 보정 대상에서 제외
- 예외: `activeTrackedMachineCount`가 `0`대인 경우 혼잡도 대신 `플레이 불가`로 표시
- 예외: 유효한 최근 제보가 없는 경우 `정보 부족`으로 표시
- 알파에서는 점포 전체 혼잡도를 계산하지 않습니다.
- 알파에서는 사볼, 마이마이 등 기종별 수요 등급을 화면 정렬에만 사용하고 혼잡도 단계 보정에는 사용하지 않습니다.

구체 산식과 표시 단계는 [crowd-level-policy.md](crowd-level-policy.md)를 따릅니다.

## 9. 알파 검증 지표 초안

| 지표 | 확인 목적 |
| --- | --- |
| 점포/기종별 제보 수 | 제보 수요와 참여 정도 확인 |
| 최근 제보가 존재하는 시간 비율 | 정보 공백 정도 확인 |
| 사진 제보 승인/반려 건수 | 기기 정보 유지 비용 확인 |
| 동일 이용자 반복 제보 빈도 | 3분 동일 이용자 쿨타임 적절성 검토 |
| 서로 다른 이용자의 연속 제보 빈도 | 1분 전체 제보 쿨타임 적절성 검토 |
| 운영 중 허위 제보 대응 건수 | 추가 방어 기능 필요성 판단 |

## 10. 남은 결정 필요 사항

- 사진 제출 화면의 개인정보 노출 방지 안내 문구
- 관리자 권한을 초기 관리자 계정에 부여하는 구현 방식
