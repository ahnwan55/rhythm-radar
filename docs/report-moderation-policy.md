# 신고 및 제보 검토 정책

## 1. 목적

이 문서는 리듬레이더 알파 단계에서 이상한 대기 상태 제보를 신고하고 관리자가 확인하는 최소 운영 흐름을 정의합니다. 목표는 자동 제재가 아니라, 운영자가 문제 제보를 빠르게 발견하고 현재 표시 상태에서 제외할 수 있게 하는 것입니다.

현재 단계에서는 정책과 화면/데이터 흐름만 정리하며, 실제 신고 기능, DB, 백엔드, 관리자 처리 기능은 구현하지 않습니다.

## 2. 신고 대상

알파에서 신고 대상은 대기 상태 제보인 `WaitReport`로 제한합니다.

| 대상 | 신고 가능 여부 | 이유 |
| --- | --- | --- |
| 대기 상태 제보 | 가능 | 허위 또는 장난 제보가 방문 판단에 바로 영향을 줌 |
| 기기 정보 변경 제보 | 제외 | 사진과 관리자 승인 흐름이 이미 있음 |
| 점포/기종 정적 데이터 | 제외 | 코드 또는 관리자 검수로 수정 |
| 이용자 계정 자체 | 제외 | 알파에서는 계정 제재를 자동화하지 않음 |

## 3. 신고 작성 규칙

- 신고는 로그인 이용자만 작성할 수 있습니다.
- 신고는 특정 `WaitReport` 하나를 대상으로 합니다.
- 신고자는 신고 사유를 선택하고 선택적으로 짧은 설명을 남길 수 있습니다.
- 신고는 해당 제보를 즉시 숨기지 않습니다.
- 같은 이용자의 같은 제보 반복 신고는 하나로 묶거나 거부합니다.

신고 사유 초안:

| 코드 | 표시 문구 | 의미 |
| --- | --- | --- |
| `WRONG_QUEUE_LEVEL` | 대기 상태가 이상함 | 현장 상태와 제보가 명확히 다름 |
| `SPAM_OR_TROLLING` | 장난/분탕 같음 | 반복적이거나 의도적인 이상 제보로 보임 |
| `WRONG_TARGET` | 기종 또는 점포가 잘못됨 | 다른 기종/점포 상태를 잘못 올린 것으로 보임 |
| `OTHER` | 기타 | 위 사유로 분류하기 어려움 |

## 4. 관리자 검토

관리자는 신고 목록에서 다음 정보를 확인합니다.

| 항목 | 설명 |
| --- | --- |
| 신고 대상 제보 | 점포, 기종, `queueLevel`, 작성 시각, 작성자 |
| 신고 정보 | 신고자, 사유, 설명, 신고 시각 |
| 주변 맥락 | 같은 점포-기종의 최근 제보 이력 |
| 처리 상태 | `PENDING`, `RESOLVED`, `REJECTED` |

관리자 처리 결과:

| 처리 | 효과 |
| --- | --- |
| 유지 | 신고를 반려하고 대상 제보는 계속 사용 |
| 숨김 | 대상 제보를 최신 상태 계산에서 제외 |
| 메모 | 운영 참고용 메모만 남김 |

알파에서는 신고 수만으로 제보를 자동 숨기지 않습니다. 단일 관리자가 신고 내용을 보고 직접 판단합니다.

## 5. 표시 및 계산 영향

- 신고가 접수된 것만으로 이용자 화면의 대기 상태를 바꾸지 않습니다.
- 관리자가 대상 `WaitReport`를 숨김 처리하면 최신 대기 상태 선택 규칙에서 제외합니다.
- 숨김 처리 후 유효한 다른 제보가 있으면 그 제보를 최신 상태로 사용합니다.
- 남은 유효 제보가 없으면 `UNKNOWN` 및 `정보 부족`으로 표시합니다.
- 숨김 처리된 제보는 운영 로그에는 남기되 일반 이용자 화면에는 노출하지 않습니다.

## 6. 제외 범위

알파 신고 시스템에 포함하지 않는 기능입니다.

- 신고 누적에 따른 자동 제재
- 신고자 신뢰도 점수
- 이용자 평판 공개
- 계정 자동 차단
- 신고 알림
- 신고 결과 상세 공개

반복 허위 제보나 악성 신고가 실제로 문제가 되면 알파 이후에 계정 제한, 신고 남용 제한, 신뢰도 가중치를 검토합니다.
