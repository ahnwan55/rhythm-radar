# MVP 이슈 백로그

## 1. 목적

이 문서는 실제 구현을 시작하기 전에 알파 MVP의 작업 단위를 이슈 형태로 정리한 초안입니다. 현재는 이슈 트래커에 등록하거나 코드를 작성하지 않으며, 범위 합의 후 각 항목을 실제 이슈로 전환합니다.

## 2. 마일스톤

| 마일스톤 | 목표 |
| --- | --- |
| M0. 정책 확정 | 대기 상태, 기기 검수, 혼잡도 표시 규칙 확정 |
| M1. 조회 및 제보 MVP | 점포/기종 조회와 로그인 이용자 대기 제보 가능 |
| M2. 관리자 검수 | 기기 수와 사진 변경 제보를 운영 가능하게 처리 |
| M3. 알파 운영 준비 | 시드 데이터, 운영 점검, 지표 확인 준비 |

## 3. 이슈 목록

### RR-001 알파 정책 결정 사항 확정

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M0. 정책 확정 |
| 우선순위 | P0 |
| 목적 | 구현 전에 화면과 데이터 모델에 영향을 주는 정책 값을 확정한다. |

**범위**

- 대기 상태 최종 표시 문구와 이용자 안내 기준 확정
- 제보 유효 시간과 동일 이용자 쿨타임 확정
- 혼잡도 표시 단계와 가동 감소 보정 방식 확정
- 증거 사진 보관 및 개인정보 노출 대응 원칙 확정

**완료 조건**

- `docs/alpha-scope.md`와 `docs/data-model.md`에서 결정 필요 항목이 확정값으로 갱신된다.
- 알파 운영자가 동일한 기준으로 제보와 기기 변경을 설명할 수 있다.

### RR-002 알파 점포 및 기종 초기 검수

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M0. 정책 확정 |
| 우선순위 | P0 |
| 목적 | 6개 알파 점포에서 표시할 기종과 기기 수의 기준 데이터를 마련한다. |

**범위**

- 알파 점포 6곳의 식별 정보 확인
- 점포별 대상 기종 목록 수집
- 기종별 총 기기 수와 가동 기기 수 초기 검수
- 기본 등록 또는 예외 등록 근거 기록

**완료 조건**

- 각 점포에 최소 하나 이상의 표시 대상 기종이 검수되거나, 보류 사유가 기록된다.
- 초기 검수 근거와 확인 시각이 기록된다.

### RR-003 점포 및 기종 상태 조회 화면 정의

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M1. 조회 및 제보 MVP |
| 우선순위 | P0 |
| 목적 | 방문 전 필요한 정보를 확인할 기본 조회 경험을 정의한다. |

**범위**

- 알파 점포 목록 화면의 표시 정보 정의
- 점포 상세에서 기종별 대기 상태, 제보 시각, 가동 기기 수, 체감 혼잡도 표시 정의
- `정보 부족`과 `플레이 불가` 상태의 표시 방식 정의

**완료 조건**

- 비로그인 이용자가 볼 수 있는 정보가 화면 단위로 문서화된다.
- 최신 제보가 없거나 기기가 미가동인 예외 흐름이 포함된다.

### RR-004 로그인 이용자 대기 상태 제보 흐름 정의

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M1. 조회 및 제보 MVP |
| 우선순위 | P0 |
| 목적 | 간결하면서 로그 추적이 가능한 대기 상태 제보 흐름을 정한다. |

**범위**

- 로그인 필수 흐름과 제보 입력 단계 정의
- 기종별 구간형 상태 선택 및 제출 결과 정의
- 쿨타임 적용 시 안내 문구 정의
- 제보 만료 후 표시 동작 정의

**완료 조건**

- 정상 제출, 비로그인 접근, 쿨타임 제한, 만료 상태의 동작이 정리된다.
- 대기 인원 숫자를 입력받지 않는다는 원칙이 모든 흐름에 반영된다.

### RR-005 제보 로그와 최소 악성 제보 대응 정책 정의

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M1. 조회 및 제보 MVP |
| 우선순위 | P1 |
| 목적 | 알파 운영에 필요한 최소한의 추적성과 대응 절차를 마련한다. |

**범위**

- 저장할 대기 제보 로그 항목 확정
- 관리자가 확인할 수 있는 로그 조건 정의
- 반복 허위 제보 발견 시 수동 처리 절차 정의
- 추가 차단 기능을 도입할 판단 기준 기록

**완료 조건**

- 로그인, 로그 저장, 쿨타임만으로 처리할 범위가 명시된다.
- 알파 범위를 넘어서는 자동 제재 기능이 별도 후속 과제로 분리된다.

### RR-006 기기 변경 사진 제보 흐름 정의

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M2. 관리자 검수 |
| 우선순위 | P0 |
| 목적 | 고장과 기기 수 변경을 이용자가 제보하고 관리자가 검증할 수 있게 한다. |

**범위**

- 고장, 수리 완료, 증설, 철수 제보 유형 정의
- 증거 사진과 설명 제출 시 필요한 항목 정의
- 접수 후 승인 전까지 공개값을 변경하지 않는 규칙 명시
- 사진 개인정보 주의 문구와 보관 정책 연결

**완료 조건**

- 이용자 제출 상태와 관리자 처리 상태가 구분된다.
- 승인된 변경만 기기 수 기준 데이터에 반영된다는 흐름이 문서화된다.

### RR-007 관리자 검수 및 기기 수 변경 이력 정의

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M2. 관리자 검수 |
| 우선순위 | P0 |
| 목적 | 공개되는 기기 수 데이터의 책임 있는 변경 경로를 만든다. |

**범위**

- 관리자 승인/반려 처리 정보 정의
- 초기 검수 및 이후 변경 이력의 기록 항목 정의
- 총 기기 수와 가동 기기 수 유효성 규칙 정의
- 잘못 승인한 정보의 정정 방식 정의

**완료 조건**

- 각 공개 기기 수 값에 최근 승인 시각과 변경 근거를 연결할 수 있다.
- 가동 기기 수가 총 기기 수를 초과하지 않는 등 기본 검증 규칙이 정리된다.

### RR-008 체감 혼잡도 규칙 검증

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M2. 관리자 검수 |
| 우선순위 | P1 |
| 목적 | 대기 상태와 가동 기기 수를 조합한 표시가 직관적인지 확인한다. |

**범위**

- `docs/data-model.md`의 계산 초안을 예시 상황에 적용
- 동일 대기 상태에서 가동 기기 감소 시 표시 변화 검토
- `정보 부족`과 `플레이 불가`의 우선순위 검토

**완료 조건**

- 대표 사례별 기대 표시 결과 표가 작성된다.
- 알파에 사용할 계산 규칙이 확정되거나 수정 사유가 기록된다.

### RR-009 알파 운영 지표 및 점검표 준비

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M3. 알파 운영 준비 |

**범위**

- 점포/기종별 제보 수, 정보 공백, 변경 제보 처리 건수 등 확인 지표 정의
- 초기 데이터 오등록 및 사진 처리 관련 점검 항목 정의
- 운영 중 정책 수정 기록 방식 정의

**완료 조건**

- 알파 시작 전에 확인해야 할 운영 체크리스트가 준비된다.
- 알파 종료 시 검토할 지표와 의사결정 질문이 정리된다.

## 4. 후속 후보 이슈

다음 항목은 알파의 필수 범위에서 제외하며, 운영 결과에 따라 후속 이슈로 검토합니다.

| 후보 | 검토 계기 |
| --- | --- |
| 신고 및 관리자 차단 기능 | 반복 허위 제보 대응 비용이 커질 때 |
| 이용자 신뢰도 또는 다수결 집계 | 단일 최신 제보 방식의 오류가 빈번할 때 |
| 즐겨찾기와 알림 | 재방문 이용자의 수요가 확인될 때 |
| 점주용 정보 수정 요청 | 점포 운영자 참여 수요가 있을 때 |
| 알파 외 점포 신청 | 대상 권역 확장의 필요성이 확인될 때 |

## 5. 이슈 전환 원칙

- 실제 이슈 생성 시 각 항목은 하나의 검증 가능한 결과물을 가져야 합니다.
- 기능 구현 이슈를 만들기 전, 관련 정책 이슈의 미결정 항목을 먼저 해결합니다.
- 알파 제외 범위는 운영 필요가 확인되지 않는 한 구현 이슈로 올리지 않습니다.
