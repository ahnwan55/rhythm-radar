# MVP 이슈 백로그

## 1. 문서 목적

이 문서는 리듬레이더 알파 MVP를 실제로 구현할 때 사용할 수 있는 작은 작업 단위 초안입니다. 현재 단계에서는 로그인, DB, 백엔드 또는 실제 제보 기능은 만들지 않고, 문서와 화면용 정적 데이터/타입 계약만 관리합니다.

기술 스택이 아직 결정되지 않았으므로 각 이슈는 특정 프레임워크가 아닌 사용자 행동, 데이터 계약, 완료 조건을 중심으로 작성합니다.

## 2. 작업 분할 원칙

- 하나의 이슈는 한 종류의 사용자 행동 또는 한 종류의 데이터 변경만 책임집니다.
- 정책값이 필요한 기능은 해당 정책 이슈가 끝나기 전에는 구현을 시작하지 않습니다.
- 조회, 제보, 관리자 승인, 운영 준비 순으로 세로 기능을 완성합니다.
- 알파 제외 범위는 별도 근거가 생기기 전까지 이슈로 만들지 않습니다.

## 3. 마일스톤

| 마일스톤 | 목표 | 구현 여부 |
| --- | --- | --- |
| M0. 결정과 검수 | 구현 전에 고정할 정책 및 초기 데이터 입력 형식 정리 | 문서 작업 |
| M1. 조회 가능 상태 | 점포와 기종별 현재 상태를 읽을 수 있는 최소 흐름 | 향후 구현 |
| M2. 이용자 제보 | 로그인 이용자가 대기 상태를 갱신할 수 있는 흐름 | 향후 구현 |
| M3. 기체 정보 검수 | 사진 제보와 관리자 승인으로 분류별 기체 수를 바꾸는 흐름 | 향후 구현 |
| M4. 알파 운영 준비 | 초기 검증, 로그 확인, 운영 점검 | 향후 구현/운영 |

## 10. 실제 이슈 생성 템플릿

실제 GitHub Issue로 전환할 때는 다음 필드를 채웁니다.

| 필드 | 내용 |
| --- | --- |
| 배경 | 이 이슈가 사용자 또는 운영자에게 필요한 이유 |
| 범위 | 이 이슈에서 다룰 단일 동작 또는 데이터 변경 |
| 제외 | 함께 처리하지 않을 기능 |
| 완료 조건 | 검증 가능한 결과 2~4개 |
| 의존 이슈 | 선행되어야 하는 정책 또는 기능 이슈 |
| 문서 연결 | `alpha-scope.md`, `data-model.md` 등 관련 근거 |

## 11. 알파 이후 후보

다음 항목은 알파의 필수 범위에서 제외합니다.

| 후보 | 검토 계기 |
| --- | --- |
| 신고 및 계정 차단 기능 | 쿨타임과 로그 확인만으로 허위 제보를 다루기 어려울 때 |
| 신뢰도 가중치 또는 다수결 집계 | 단일 최신 제보의 오류가 반복될 때 |
| 즐겨찾기와 혼잡 알림 | 반복 방문 사용자 수요가 확인될 때 |
| 점주용 관리 요청 | 점포 운영자의 참여 필요가 확인될 때 |
| 점포 신청과 권역 확대 | 알파 권역 밖의 수요가 확인될 때 |
